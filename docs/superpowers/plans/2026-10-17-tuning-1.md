### T1: `prompts/ideate.v4.md`, abstract quality bar (owner decision 1)
- New version (keep v1–v3 for provenance). Copy v3, then:
  - Remove every lead-form, contact-form, lead-flow, uptime/browser-automation and web-agency example.
  - Remove the "do not reuse the benchmark's buyer or problem…" sentence; it no longer applies.
- Rewrite the five principles as abstract dimensions, with no examples tied to one industry:
  1. A costly problem buyers feel but existing tools don't solve, often invisible, manual, or falling between systems.
  2. A clear argument for why current approaches fall short.
  3. The best buyer is whoever feels the pain most often or across many customers. That may not be the obvious buyer.
  4. Delivery can be mostly automated, so one engine serves many clients.
  5. No licensing or regulation is needed, and a pilot is fast.
- Add: "Ideas must vary in industry, buyer and mechanism. Monitoring/alerting is only one of many possible mechanisms. Also consider recovery of lost money, automation of recurring manual work, data products, integrations between systems, and compliance-driven work."
- Keep everything else from v3: minSignals distinct sites, `<prior-ideas>` diversity, `wrapUntrusted`, anti-goals.
- `loadPrompt` picks the highest version automatically. Update any test that asserts `ideate.v3`.
- Test: the rendered ideate prompt contains none of "lead", "contact form", "agency" or "uptime" (case-insensitive word match), and does contain the mechanism-variety sentence.

### T2: Per-sector pain phrases + broader WordPress plugins (owner decision 2)
- New `src/pipeline/pain-phrases.ts`. Export `GENERIC_PAIN_PHRASES` and `SECTOR_PAIN_PHRASES: Record<string, string[]>`, keyed by the exact sector strings seeded for market `ca-us` (read `src/db/seed.ts`). Each sector gets 4–6 specific, search-friendly phrases (2–5 words) describing time or money loss in that sector. Examples:
  - dental clinics: "no-show patients", "insurance claim denied", "manual appointment reminders"
  - property management: "chasing rent payments", "maintenance request backlog"
  - logistics/freight brokers: "invoice disputes carrier", "manual load tracking"
- `GENERIC_PAIN_PHRASES` replaces the old `PAIN_PHRASES` and must NOT contain "lost leads" or "silently failing". Use broad ones: "manual every week", "spreadsheet nightmare", "keeps breaking", "wasting hours", "double entry", "copy paste between systems", "chasing payments", "no way to know if".
- `phrasesFor(sector)` returns that sector's phrases plus 2 generic phrases chosen with the injected `random`. Unknown sector → generic only.
- `harvest.ts`:
  - The `open` and `sector` seeds build queries from `phrasesFor`.
  - Remove the old `PAIN_PHRASES` export, and update its imports and tests.
- `wordpress.ts` `DEFAULT_WP_SLUGS` becomes a broad list. Keep at most 2 form/email plugins (`contact-form-7`, `wp-mail-smtp`) and add: `woocommerce`, `bookly-responsive-appointment-booking-tool`, `simply-schedule-appointments`, `paid-memberships-pro`, `updraftplus`, `wordpress-seo`, `the-events-calendar`, `easy-digital-downloads`, `mailpoet`, `sliced-invoices`.
- Harvest uses `source.slugs` when the source exposes them, otherwise `DEFAULT_WP_SLUGS`. This fixes the dead `slugs` option.
- Tests:
  - Every seeded `ca-us` sector has ≥4 phrases.
  - Generic phrases exclude "lost leads" and "silently failing".
  - Harvest with seed sector `['dental clinics']` and a deterministic `random` sends queries containing a dental phrase.
  - Harvest uses custom wordpress slugs when present.

### T3: Hybrid evidence counting in the gate (owner decision 3)
- `src/pipeline/gate.ts` evidence check. Define the community platforms as these registrable domains: `ycombinator.com`, `stackexchange.com`, `stackoverflow.com`, `github.com`, `wordpress.org`. Put them in one exported constant.
- **Unit counting:**
  - For community platforms: count distinct threads, capped at **2 per platform**. A thread is the URL with the fragment stripped. Keep the query string, since HN uses `?id=`.
  - Every other site counts **once** per registrable domain, as today.
  - Unparseable, non-http(s), IP and banned URLs are excluded, as today. Fail closed.
- Pass iff `units ≥ minSignals`. The reasoning string lists the breakdown, e.g. `"3 independent sources: ycombinator.com ×2 threads, example.com"`.
- Tests:
  - 5 different HN threads plus 0 other sites → 2 units (fails at minSignals 3).
  - 2 HN threads + 1 GitHub issue → 3 units (passes).
  - The same HN thread with different fragments → 1.
  - 3 distinct non-community domains → 3.
  - A banned URL is excluded.
  - The existing registrable-domain tests still pass, with updated expectations where needed.
