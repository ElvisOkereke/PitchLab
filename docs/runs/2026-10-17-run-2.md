## Read on case quality

- **Neither case is pitch-worthy as is.** The open-run case has a real buyer insight (the PE roll-up/DSO ops leader
  sees the same front-desk leak at every branch and pays for the marketing that makes phones ring). But its 3.7× ROI
  rests on two `❌ unsupported` $150 inputs and an assumed 52 lost leads per location per year. It also needs a TCPA
  consult before the first test call. Worth an owner gut-check, not a pitch.
- **The benchmark case got more honest and less attractive.** It now concedes the `generic` gate failure, narrows the
  edge to CRM/webhook checks, and computes 0.24× ROI. That is a fair finding: per-site pricing against an unknown
  failure rate does not pay back for the agency.
- **Ideation is broader, but the funnel still selects lead capture.** Money-recovery, data-product and rules-engine
  ideas now appear (rent-notice engine, invoice reconciliation, ZIP demand scores), but the screen ranks them below
  the monitoring ideas, so the gate never sees them.
- **Competitor flags mislead.** 5 of 12 (open) and 6 of 8 (benchmark) competitor links show `❌ unsupported`, mostly
  because the checked claim is "Name: Not published" pricing, which no page can confirm. The scorer reads these flags
  and marks evidence down for it.
- **Evidence sections carry noise.** The open case's signals include an off-topic GitHub contractor-bid issue and a
  WordPress refund thread, one of them showing raw `&#8217;` entities.

## Open points (need a decision, not a bug fix)

1. **What a competitor link's check should assert.** Today it checks `Name: pricing`. For "Not published" pricing
   this is an absence claim that always fails. Options: check that the page describes the named product (and check
   pricing only when a figure is given), or skip pricing in the claim text. This changes the export lookup key, so it
   needs a decision.
2. **GitHub issue pages render the body client-side.** The fetcher sees about 3,900 chars of page chrome, so a
   genuine API-harvested quote is flagged `❌`. Options: verify GitHub signals through the API, or trust quotes from
   API sources.
3. **The screen favours lead-capture ideas.** Options: a diversity quota at screen (e.g. at most 2 entrants per
   mechanism/buyer type), or penalise similarity to the benchmark idea's embedding at screen.
4. **Signal relevance.** Cases display every signal linked to the idea, including off-topic ones; and HTML entities in
   quotes are not decoded (an existing follow-up).
