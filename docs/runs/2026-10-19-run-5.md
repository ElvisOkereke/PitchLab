## Read

1. **Tuning-4 shuffled failures; it did not create passes.** `generic` kills went 4 → 2 and are now about function, so option (a) worked as intended. The ideas that cleared `generic` died on autonomy, control or regulation instead. 0/5 again.
2. **Autonomy is now the main constraint (4/5),** and ideation never sees it: `<already-sold>` carries only `generic` kills. All four autonomy kills share one pattern: the core decision needs facts the service doesn't hold (legal entitlement, physical progress, invoice dates, tenant permissions).
3. **The operator-voice rule moved the bottleneck from the gate to ideation.** Only 17 of 43 signals count and 0 are neutral, so ideas collapsed onto two signal sets (5 of 8 share the same 5 signals), three sectors produced nothing, and output fell to 8 ideas. The evidence that does pass is fragile: 4 of 5 entrants reach 3 units only through a mis-tagged GitHub problem-catalog issue.
4. **Nothing is pitch-worthy.** The closest is **Customer Lien & Pay-Risk Watch for trade subcontractors**, which passed 5 of 6 checks but duplicates NCS's monitoring. A re-run would need a verified gap first.
5. **Next highest-leverage change:** feed every gate kill reason (not just `generic`) into ideation, and add an ideate rule matching the gate's autonomy test: "the core output must be computable from data the buyer already hands over, with no per-item expert judgement". Evidence: 4/5 autonomy kills, all for the same reason, while generic is now largely aligned.
6. **Second, fix signal supply before trusting the evidence rule:**
   - Tell `extract-signals` that problem catalogs, idea lists and JTBD templates are not operator voice (exclude them, or tag them vendor/neutral).
   - Make WordPress queries follow the chosen sectors. They still use default slugs (`wp-mail-smtp`, `easy-digital-downloads`), and that is where the Auth-Retirement and Unbilled ideas came from.
   - Find out why `harvest-research.v5` returned no association or regulator sources.
